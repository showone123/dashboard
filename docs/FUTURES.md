# 期货工具箱（2026-09-18）

在左侧「工作台」末尾新增「期货工具箱」，五个分类是期货手续费、期权手续费、期货公司、期货资料、期货软件。其他导航和既有页面不变。每类支持搜索、分类筛选、收藏、来源链接、最后成功更新时间和立即刷新。

## 数据范围与呈现

- 期货手续费：提取 `heyuetbl` 表中所有合约行；保留元、万分之、保证金和手续费来源时间，不重新计算收费。
- 期权手续费：首页是 88 个品种入口。点击「查看费用明细」在本页显示对应品种表格；首个未缓存品种只需首次抓取，之后直接读缓存。快照预置黄金期权明细，其余品种按需获取。
- 公司、资料、软件：提取用户所给 URL 的当前列表页（首次快照分别为 10、24、10 条），不是整站归档。页面明确标注此范围；通过来源链接浏览分页和完整文章。文章只保存标题、链接和来源标注时间；不复制文章全文或下载软件安装包。
- 815 条期货手续费和所有其他初始内容是实际抓取快照，不是示例生成数据。`updated_at` 为抓取成功时间，不是费用生效时间。来源未标注时间时显示「未标注」。
- 收藏保存在当前浏览器，按当前登录用户 ID 分区；不跨设备同步。公开数据快照与账号资料分离。

## 缓存与刷新

同一 Python 服务进程新增两个精确路由：

| 路由 | 行为 |
|---|---|
| `GET /api/futures?category=futures` | 仅读取缓存，不触发或等待爬虫 |
| `POST /api/futures/refresh?category=futures` | 非阻塞提交刷新，立即返回当前快照与刷新状态 |

分类为 `futures/options/companies/articles/software`，期权详情为 `option:<品种代码>`；详情代码必须存在于已抓取的期权目录中。POST 要求 `X-FluxDesk-Request: 1`，同源 Origin 校验，无跨域许可。接口只提供公开来源数据，不接受目标 URL，不读取用户、订阅或客户数据；既有云服务权限和生产访问配置未改变。

服务启动后后台检查五个主分类，每六小时更新过期数据；每类刷新至少间隔 60 秒，同类请求合并。最多两个抓取线程、八个待处理分类，超时 20 秒、响应上限 8 MiB。网络、解析或写盘失败均保留上次成功内容和时间；写盘用临时文件加原子替换。浏览器也保留快照，服务不可达时可继续显示本地数据。

默认磁盘缓存为部署目录外 `../.futures-cache/`，可用环境变量 `FUTURES_CACHE_DIR` 指向可写的持久化目录。普通进程重启会恢复磁盘数据。**若部署平台在重新发布时替换整个文件系统，需要将该变量指向平台持久化卷**；未配置时仍有打包快照及原浏览器缓存兜底，但无法保证所有用户取得上一容器最新快照。多实例各自缓存，不提供跨实例同步。

## 部署契约变更与 WorkBuddy 操作

此次有意扩展 `dist/server.py`，原因是用户要求站内立即刷新及失败保留旧数据，原纯静态服务不能完成服务端抓取。没有引入第二个服务、npm、Redis、数据库驱动或迁移。

- 服务器源码迁至 `build/server.py`，与 `build/futures_service.py`、`build/futures_seed.json` 一同由构建复制到 `dist/`。
- `contract.json` 更新服务器 SHA-256/字节数并记录新增收藏/快照键前缀及限流参数；原 Excel、通知、认证配置和数据库契约不变。
- 保留 `PORT`、`0.0.0.0`、`/.cloud` 排除、SPA 兜底。新增服务端模块及隐藏目录不作为静态文件暴露。
- 新键 `fluxdesk_futures_favorites_v1:<用户ID>`、`fluxdesk_futures_snapshot_v1:<分类>` 不迁移、不覆盖任何既有 localStorage 键。
- 数据库不变；无需执行 SQL。

WorkBuddy 拉回源码后运行 `python verify.py`，退出码 0 后按原流程发布整个 `dist/`。启动命令仍是 `python server.py`。确认服务器可出站访问 `https://www.9qihuo.com`，缓存目录可写；按上面说明配置持久化目录。请勿只覆盖 HTML，否则刷新接口不会生效。

部署后验收：登录后打开工具箱 → 搜索合约 → 收藏并重开 → 切换五分类 → 打开黄金期权明细 → 立即刷新 → 断网后仍有缓存提示与旧内容。确认原总览、市场看板、数据中心、风险日志、历史记录和运营台正常；`/.cloud` 仍由网关处理。
